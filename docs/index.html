Route every prompt to the model built for it.

A Mixture-of-Models router, written in Rust: it classifies each request in-process with a local embedding model and dispatches it to whichever backend actually handles that kind of task — no Python at inference time, no training required to start.

How a request moves through it

router/src/server.rs

Every stage below is a real, separately-timed span — set OTEL_EXPORTER_OTLP_ENDPOINT and each request becomes one trace with per-stage latency in Jaeger.

01
Prompt guard
Reject requests matching known jailbreak phrases before any embedding or backend call happens. Extendable via config.
02
PII scan
Block or redact emails, phone numbers, SSNs, card numbers, and IPv4 addresses in the message before it goes any further.
03
Embed
Candle + MiniLM turn the (possibly redacted) message into a 384-dimension vector, in-process — no Python, no ONNX runtime.
04
Cache check
Non-streaming requests check a semantic cache first; a near-duplicate prompt returns a cached response and never reaches a backend.
05
Route
Cosine similarity against category examples, or a trained classifier, picks the category — or falls back to a default backend.
06
Dispatch
Proxy to that category's backend with the model field rewritten, or pipe its Server-Sent-Events response straight through unbuffered.

Two ways to route, both measured

eval/run_eval.py · 100 held-out prompts

Neither number is assumed. Both come from the same 100-prompt labeled set, held out from whatever the router was given to learn from.

Similarity 88%

Cosine similarity against 12 example utterances per category. Zero training — edit the category list in routes.yaml and it adapts instantly. The default.

  • No training artifact to go stale
  • Precision drops on genuinely ambiguous prompts
  • Doubling examples from 6→12 took accuracy 71%→88%

Classifier 94%

A logistic-regression probe trained on the router's own /embed output for those same 60 examples — one embedding implementation, never re-derived in Python.

  • Beats similarity, but goes stale if categories change
  • Weights are committed — works immediately, no retraining
  • Opt-in via routing.strategy: classifier
getting the classifier there
C = 1.0 (default)
7%
cross-validated C
63%
+ re-tuned threshold
94%

First attempt scored worse than random: 60 examples in 384 dimensions, unregularized, memorized the training set and generalized to nothing. 5-fold cross-validation on the training examples (never the eval set) fixed the regularization; every remaining miss was the classifier declining to guess, not guessing wrong — so a re-tuned confidence threshold closed most of the rest.

What ships with it

router/src/
security

PII & prompt guard

Regex-based PII detection (block or redact) and jailbreak-phrase blocking, both off by default and toggled per deployment.

transport

SSE streaming

"stream": true skips the cache and pipes the backend's response straight through, unbuffered, headers and all.

performance

Semantic cache

Brute-force cosine cache short-circuits near-duplicate prompts before they ever reach a backend model.

observability

OpenTelemetry tracing

Per-stage spans exported over OTLP; docker-compose ships Jaeger alongside the router for zero-config trace viewing.

deployment

Kubernetes

Deployment with health probes, a ClusterIP Service, and a Kustomization that bakes config into a ConfigMap.

quality

CI on every push

fmt --check, clippy -D warnings, and the full test suite, verified green on GitHub's own runners.

Get it running

~2 minutes, first model download aside
1. clone and start a backend to route to
git clone https://github.com/Shyamcharan06/semantic-router-rs
cd semantic-router-rs
cp config/routes.example.yaml config/routes.yaml

# mock backend: echoes back which model it was routed to,
# no real API key needed to see routing work
python -m venv .venv && .venv/bin/pip install -r eval/requirements.txt
.venv/bin/python eval/mock_backend.py &
2. run the router
# first run downloads ~90MB of MiniLM weights from the HF Hub
ROUTER_CONFIG=config/routes.yaml cargo run --release
3. see a routing decision
curl "http://localhost:8088/route?q=Write+a+Python+function+to+sort+a+list"

# {"category":"coding","model":"coder-model","score":0.91...}
4. or the full round trip
curl http://localhost:8088/v1/chat/completions \
  -H 'content-type: application/json' \
  -d '{"messages":[{"role":"user","content":"Write a poem about the sea"}]}'
